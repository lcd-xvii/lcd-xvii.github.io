# OI 高效、罕见、实现简单的数据结构

## 配对堆（Pairing Heap）

非常 NB 可并堆。

|操作|复杂度|
|-|-|
|合并 `meld`|$O(1)$|
|插入 `push`|$O(1)$|
|堆顶 `top`|$O(1)$|
|弹出 `pop`|$O(\log n)$|
|修改 `decrease_key`|$\Omega(\log\log n),O(2^{\sqrt{\log\log n}})$|

**合并**：把大堆挂成小堆的根的子节点。

**插入**：把键当作大小为 $1$ 的堆合并。

**堆顶**：直接访问根节点。

**弹出**：弹出堆顶后，会留下其所有儿子构成的森林。

这里先从左到右将其相邻的儿子两两合并（配对），再**从右到左**把堆并成一个。

这里两两配对、及反向合并的操作，是因为合并时通常直接将堆挂在根下，如果单趟合并很可能造成其儿子严重不平衡而复杂度退化。
先配对来减轻局部不平衡性，再反向合并，抵消部分不平衡。

**修改**：虽然复杂度没有严谨的分析，但是其操作十分简单：只需把这个节点割掉，再将新节点合并回去即可。

> **评价**
>
> 真的 NB。
> 我说它完胜斐波那契堆，而且 `__gnu_pbds` 直接可用。

## 随机堆

斜堆优化版。

斜堆的固定交换左右儿子可能退化，随机堆改为 $\frac12$ 的概率交换。
虽然所有的复杂度都是 $O(\log n)$，但是常数非常之小，另外可持久化。

> **评价**
>
> 虽然复杂度较劣，但是真的好写。

## Crit-bit Tree

压位 Trie 的一种。

维护字典树的**位**分支位置，可以 $O(1)$ 选择子树并下行。
最后到叶子再完整比较一遍，做到 $O(k)$ 的插入、查找、有序遍历等。

> **评价**
>
> 理论复杂度和哈希表一致，但是好像在 Trie 问题和 Hash 问题里都不是很适用，场景有限。

## XOR Linked Tree

树形 DP（及所有自底向上的树上问题）的 Brilliant Trick。

每个节点存度数和**其相邻节点编号的异或值**。遍历时先从叶子节点开始，此时其值就是出点。每次剥掉度数为 $1$ 的点，并将其邻点的度数减 $1$、异或值异或回去，那么每个点在度数为 $1$ 时都恰好存有唯一出点的编号。

适用于从底到顶的树形 DP 问题，例如 LCA 可以用其算出每个节点的子树 `size`，再用 DFS 序解决 $O(\log n)$ 或 $O(1)$ 的查询。

> **评价**
>
> 技巧中最佳，可惜不是完整算法，只是复杂度不变的常数优化。

## Sqrt Tree

ST 表的优化+可修改实现。

这个还是比较常见的，就是分块，然后每个块做 ST 表。时间复杂度 $O(n\log\log n)$，同时可以有 $O(n)$ 的修改复杂度。

> **评价**
>
> 分块的数据结构不优雅，但是应用很多。
