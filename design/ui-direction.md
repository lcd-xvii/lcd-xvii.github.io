# UI 设计参考与方向（工作前准备）

> 目的：在动本站代码之前，先把「参考源 → 现状审计 → 方向候选 → 克制规则」定下来，避免边写边改样式。
> 配套可视预览：`design/preview.html`（用浏览器打开，右上角可切浅色/深色）。

## 0. 关于「搜索」

本会话的 web search 通道返回 401（搜索端点的 API key 无效），因此没有用搜索摘要，而是直接抓取参考站的 HTML/CSS 做数值提取，并审计了本仓库现有的 `assets/css/app.css`、`assets/css/home.css`。文中所有具体数值都是抓取/读码得到的，不是凭印象写的。

已抓取：`paco.me`（含其 CSS chunk）、`vercel.com/geist/colors`、`ui.shadcn.com`、`linear.app`、`www.awwwards.com/websites/minimal/`（后者仅成功取到 HTML 外壳，正文列表由 JS 渲染，未取到）。超时/被拒：`rauno.me`、`rsms.me/inter/`。

## 1. 参考源与可借用的东西

| 参考 | 抓到的具体事实 | 可借用 | 不借 |
| --- | --- | --- | --- |
| **paco.me** | 单一 `Inter`；正文测量宽 `--content-width:640px`；Retina 下 `--border-thin:.5px`；正文色用带 alpha 的 `#1c1c1ce6` / `#ffffffe6` 而非纯黑纯白；大标题 `letter-spacing:-.05em`；12 级灰阶（`--mono1…mono12`）取代一堆散装灰色；正文字号仅 13/14/16/17 四档 | 行宽上限、hairline 分隔、灰阶变量化、alpha 文本色、标题负字距 | 极窄的 640px 用在文档正文太窄；几乎是纯作品集排版 |
| **Vercel Geist** | 中性灰面 + 极浅 1px 边框 + 单色强调；颜色以 10 级灰度阶梯 + 单色 accent 组织；强调色只出现在交互元素 | 中性面/边框双色制、accent 只给可交互元素 | 品牌红黑配色的强烈辨识度 |
| **shadcn/ui** | 主题完全由 CSS 变量表达（`--background / --foreground / --muted / --border / --ring`），组件不写死颜色；`--radius` 单变量派生所有圆角 | 「一个 radius 变量派生全部圆角」、语义化 token 命名 | 大量组件默认圆角 6–8px 带来的“通用后台感” |
| **Linear** | 高密度但极安静：字号阶梯短、对比靠字重与灰阶而不是色彩；列表行高固定 | 行式列表、短字阶、靠灰阶分层 | 深色近黑 + 光晕的品牌视觉 |
| **rustdoc / docs.rs**（本站现有血统） | 本站 `app.css` 的配色与结构即从 rustdoc 提取（`--accent:#3873ad` 等），左侧栏 + 正文 + TOC 三栏、行式导航项 | 信息结构、与 `oi-docs` 的一致性 | 未收敛的重复覆盖层（见下节） |
| **出版社/印刷排版惯例**（Tufte、书籍版心） | 版心 62–72 字符、标题与正文同族不同重、分隔线 1px 且不抢眼、页边大于行距 | 「纸感」：靠留白与线分层，不靠卡片与阴影 | 衬线正文（中文衬线在小字号屏上可用性下降，仅保留为可选开关） |

三条被反复验证的共性，构成了本方案的地基：

1. **克制 = 变量少**。所有做得安静的站点，颜色/圆角/字号/阴影的取值集合都极小（单强调色、一两个圆角、一条阴影）。
2. **分层靠线与面，不靠阴影**。阴影只用于真正浮起的层（弹窗、下拉）。
3. **强调色是稀缺资源**。一旦图标、标签、徽章、链接全用它，就等于没有强调。

## 2. 现状审计（`index.html` + `assets/css/*.css`）

结构本身是好的（信息层级清楚、可访问性有 `skip-link`、主题持久化、无第三方 UI 框架）。问题集中在样式层：

1. **两轮回写**。`app.css` 前段是一套通用样式，后段又从 `.brand{}` 开始重写一遍（注释写「Rustdoc-inspired…」），`.card`、`.toc`、`.brand`、`.hero`、`.tag` 等被定义 2–4 次，后写的靠顺序覆盖前面的。改一个数值要读完整份文件才知道哪条生效。
2. **「无动画」靠 `!important` 抵消**。`app.css` 里 `*,*::before,*::after{transition:var(--tt)}` 给所有元素加了过渡，`home.css` 再用 `.home *{transition:none!important}` 全量关掉。目标是对的，手段是互相对抗。
3. **字号档太多**：11/12/13/14/15/16/17/18/21 混用，末段还整体上调 1–2px，同一元素在不同位置尺寸不同。
4. **圆角 8 档**：`999 / 12 / 10 / 8 / 7 / 6 / 5 / 4 / 3px` 全出现过。
5. **阴影 4 种**：`0 1px 2px`、`0 0 24px`、`0 8px 28px`、`0 18px 55px`。
6. **强调色过载**：`--accent` 同时用于链接、图标、tag、badge、TOC 当前项、卡片 hover 边框、logo、滚动条高亮，强调等于无强调。
7. **残留样式**：`.brand .logo` 先给 `linear-gradient(135deg,#0969da,#8250df)` + `::selection`，后段才改成 `var(--accent)`；渐变与「克制」直接冲突。
8. **断点 5 套**：`520 / 600 / 860 / 1500 / 1600px`，其中 `1500` 与 `1600` 两处都用来定 TOC 的 `position:fixed`。
9. **三主题语义不稳**：light 蓝、dark 绿、ayu 橙，同一个「强调」在三种主题里色相完全不同；换主题等于换了一套设计语言。
10. **卡片 hover 位移**：`transform:translateY(-2px)` 在 `oi-docs` 有、主页被禁用，同名元素两种行为。

结论：不需要推翻重做，需要一次**收敛（consolidation）**：确定一套 token、删掉覆盖层、把强调色的使用权收窄。

## 3. 三个方向

三个方向都用同样的内容（hero → 入口/项目/联系 → footer）和同样的三层结构，差别只在「用什么分层」。全部给出浅色 + 深色两套值；`ayu` 主题在三个方向里都只做变量覆盖。

主张：**没有卡片，只有纸、线和字**。暖白纸底、近黑墨、一条氧化铁红的强调线。适合「一个人」的个人主页气质。

### 我的建议

- 想「稳、和 `oi-docs` 一套」→ **B 做骨架 + A 的排版克制**：变量与字族沿用现站（零风险），行宽收到 66–72ch、删掉阴影与卡片位移、强调色只留给「链接 / 当前项 / 焦点环」。
- 想「有点工程气质但不吵」→ **D 图纸**（这是我认为最适合本站的第二选）。
- 想「更现代、接受多一个字体」→ **C 静网格**。
- 想「一眼记住」→ **F 瑞士**，但只用在主页。
- 想「极端安静」→ **G 编者**，前提是内容撑得住。

## 4. 克制规则（验收清单）

改完后逐条对照，任何一条不满足就算没做完：

1. 强调色**一种**，且只出现在链接、当前项、焦点环；图标、眉标、徽章一律用 `--ink-2`。
2. 圆角**最多两档**（内容 / 浮层），由单个 `--radius` 派生。
3. 阴影**最多一种**，只给浮层；页面内不出现阴影分层。
4. 字族 ≤ 2；字号档 ≤ 5；行高只有两个值（正文 1.7–1.75、标题 1.2–1.3）。
5. 分隔线一律 `1px solid var(--line)`；不用渐变造面、不用 `box-shadow` 造线。
6. 位移/缩放类动效为 0；只允许颜色与透明度 ≤ 200ms，且 `prefers-reduced-motion: reduce` 下全部归零。
7. 每屏只有一个视觉重心（标题或当前项），其余元素退到 `--ink-2`。
8. 正文对比度 ≥ 4.5:1，辅助小字 ≥ 3:1（浅色放到 `--ink-2` 为止，不再更浅）。
9. 三主题（light / dark / ayu）只通过变量覆盖实现，禁止再写 `[data-theme="dark"] .xxx{}` 这样的组件级规则。
10. 空态/错误态用「文字 + 一条线」，不用彩色块和图标。
11. 同一属性只在一处定义；`app.css` 里现存的两轮回写必须合并。
12. 断点收敛到 2 个（`860px` 侧栏折叠、`600px` 手机）。
